## Your project

```text
my-docs/
  docs/
    init/
      _category.json
      intro.mdx
      getting-started.mdx
    examples/
      _category.json
      markdown.mdx
  public/
    images/
  package.json
  rdx.config.ts
  .gitignore
  README.md
  .rdx/
```

Use `docs/` for content, `public/` for public files, and `rdx.config.ts` for
configuration. The creator includes example pages that you can replace.

`home.tsx` is optional and belongs beside `rdx.config.ts`. It is only used
when imported and assigned to `homepage.component`.

## The internal application

`.rdx/` is generated by `rdx prepare`, `rdx dev`, `rdx build`, and
`rdx start`. It contains the Next.js application and its build output.

Keep it out of version control. Do not treat it as a source directory:
preparation refreshes its runtime files. Your source of truth is the project
configuration, content, assets, and any components you own.

## Categories and URLs

The first folder level becomes sidebar categories. An optional `_category.json`
sets a category's title and order. Nested files retain their path, but nested
sidebar groups are not part of the current release.

In generated projects, `docs/init/intro.mdx` becomes `/docs/init/intro`.
This official development website uses the Canary prefix and keeps its own
short filename routes. Prefer relative MDX links so your content does not
depend on either adapter's URL format.

## Versioned

With the optional versioning plugin, `versions.json` lists snapshots and
`versioned_docs/` stores them. Neither is needed to write your first page.
Learn more in [Versioning](../cat-04/versioning.mdx).
