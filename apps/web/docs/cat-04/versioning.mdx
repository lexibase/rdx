## Activate the plugin

Versioning is optional. A new project works without `versions.json` or snapshots.

<Tabs defaultValue="pnpm">
  <TabsList aria-label="Activate versioning">
    <TabsTrigger value="pnpm">pnpm</TabsTrigger>
    <TabsTrigger value="npm">npm</TabsTrigger>
    <TabsTrigger value="yarn">yarn</TabsTrigger>
  </TabsList>
  <TabsContent value="pnpm">
pnpm rdx add versioning
  </TabsContent>
  <TabsContent value="npm">
npm exec -- rdx add versioning
  </TabsContent>
  <TabsContent value="yarn">
yarn rdx add versioning
  </TabsContent>
</Tabs>

This activates the plugin in your configuration. For manual setup, see
[Plugins](./plugins.mdx).

## Create a release snapshot

When the current documentation is ready for a release:

<Tabs defaultValue="pnpm">
  <TabsList aria-label="Create a release snapshot">
    <TabsTrigger value="pnpm">pnpm</TabsTrigger>
    <TabsTrigger value="npm">npm</TabsTrigger>
    <TabsTrigger value="yarn">yarn</TabsTrigger>
  </TabsList>
  <TabsContent value="pnpm">
pnpm rdx version 1.0.0
  </TabsContent>
  <TabsContent value="npm">
npm exec -- rdx version 1.0.0
  </TabsContent>
  <TabsContent value="yarn">
yarn rdx version 1.0.0
  </TabsContent>
</Tabs>

RDX copies `docs/` into `versioned_docs/version-1.0.0/` and adds the version to
`versions.json`:

```json
{
  "active": ["1.0.0"],
  "archived": []
}
```

Snapshots are not overwritten. Continue editing `docs/` for your next release;
the snapshot retains its previous content. This command versions documentation,
not npm packages, Git tags, or your application's source.

## Read and switch editions

In a generated project, the live page stays at `/docs/init/intro`; its snapshot
is at `/docs/1.0.0/init/intro`.

The navbar dropdown lets readers switch editions. RDX keeps the same document
when it exists in the destination; otherwise it opens that edition's first page.
Pre-release and outdated edition notices provide context. Search stays scoped
to the selected version.

The official RDX development site calls its live edition **Canary**. Generated
projects call theirs **Current**.

## Archive an older edition

Move its label from `active` to `archived` in `versions.json`, keeping the
snapshot directory intact:

```json
{
  "active": ["1.1.0"],
  "archived": ["1.0.0"]
}
```

This example requires both snapshots to exist. The first active entry is the
current published edition. Archived content remains accessible and searchable
within its edition; archiving is not deletion or access control.

## Assets and deployment

Snapshots contain documentation, not copies of `public/`. Use distinct asset
filenames when an older image must remain unchanged.

Commit your manifest and snapshots with the source content. Rebuild and redeploy
after changing versions. Do not run snapshot creation on every build or request.
