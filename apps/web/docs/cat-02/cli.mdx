## Creator and runtime

The creator, `@lexibase/create-rdx`, generates a new directory. The runtime command,
`rdx`, belongs to the installed `@lexibase/rdx-next` package and works inside an
existing documentation project. You do not need a global RDX installation.

## Create a project

```bash
pnpm create @lexibase/rdx@latest my-docs
```

Omit the name to get an interactive prompt. The directory name is preserved;
the generated package name is normalized to lowercase. Existing directories
are not overwritten.

| Creator option | Effect |
| :------------- | :----- |
| `--help` | Show usage without creating a project |
| `--version` | Print the creator's version |
| `--skip-install` | Create files and leave installation to you |

## Development and production

Run these from the generated project root:

```bash
pnpm dev
pnpm build
pnpm start
```

`dev` starts the development server, `build` prepares a production build, and
`start` serves that build. With npm, use `npm run dev`, `npm run build`, and
`npm run start`.

The underlying commands are `rdx dev`, `rdx build`, and `rdx start`. They prepare
the internal app automatically. Forward Next.js arguments when needed:

```bash
pnpm rdx dev --port 3001
pnpm rdx start --hostname 127.0.0.1 --port 3001
```

For npm, use `npm exec -- rdx dev --port 3001`.

## Prepare without starting a server

```bash
pnpm rdx prepare
```

This validates configuration and prepares `.rdx/`, including public assets and
configured plugin preparation. It does not create a documentation snapshot.

## Plugins and snapshots

```bash
pnpm rdx add versioning
pnpm rdx version 1.0.0
```

`version` is registered only after the versioning plugin is configured.
See [Plugins](../cat-04/plugins.mdx) and [Versioning](../cat-04/versioning.mdx)
before creating snapshots. `rdx --help` lists the built-in command usage.

The installer can be selected explicitly with
`rdx add versioning --package-manager npm` (or `pnpm` / `yarn`). Normally RDX
detects the package manager from how the command was invoked.
