title: Catch documentation problems before you build
---

You can now do more with `rdx check` while you write. It can suggest a fix for a
broken link, point out pages that other documents never link to, and tell your CI
when a pull request introduces a new warning.

## Run the check as soon as you create a project

New projects include a `check` script. Run `pnpm check` after editing a page to
find broken links, missing images or downloads, and invalid Markdown or MDX
without building the site. In an existing project, run `pnpm exec rdx check`.

## Find the link to fix

Say you moved `installation.mdx` into `getting-started/` and a guide still
points to its old file location. When RDX finds one close match, it suggests
the new path right below the error.

```text
docs/guides/setup.mdx:12:1 [page] "./installation.mdx": "guides/installation.mdx" does not exist in this documentation source.
  Did you mean "../getting-started/installation.mdx"?
```

RDX can also suggest a nearby heading ID for a broken section link. If an old
URL still works through `redirectFrom`, the check reports it as a warning and
suggests the current URL, preserving the query and section fragment.

## Keep new warnings out of your pull requests

The check warns about pages with no incoming links from other documents or
release notes. Suppose your site already has 14 warnings. A pull request fixes
one unlinked page and introduces another. The total stays at 14, so a warning
limit of 14 passes. A baseline catches the new unlinked page.

Save the current warnings and commit the file with your project:

```sh
pnpm exec rdx check --write-baseline rdx-check-baseline.json
```

Then check against that file in CI:

```sh
pnpm exec rdx check --baseline rdx-check-baseline.json
```

An existing warning still matches if its line number changes. New warnings and
errors fail the check. Use `--max-warnings N` to also cap the total, or add
`--json` to send the report to a script that adds annotations to your pull
request.

See [Checking documentation](/docs/6.6.0/checking) for the options and a
GitHub Actions example.
