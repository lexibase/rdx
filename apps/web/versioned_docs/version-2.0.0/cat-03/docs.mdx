## Your project

Organize your documentation, assets, and custom React components as follows:

```text
my-docs/
  components/
    home.tsx
    logo.tsx
  docs/
    init/
      _category.json
      intro.mdx
      getting-started.mdx
    examples/
      _category.json
      markdown.mdx
  public/
    images/
  package.json
  rdx.config.ts
  tsconfig.json
  .gitignore
  README.md
  .rdx/
```

Use `docs/` for content, `public/` for public files, and `rdx.config.ts` for
configuration. The creator includes example pages that you can replace.

## Custom components

Create a `components/` folder at the project root for your own React components,
such as a [custom logo](../cat-04/custom-logo.mdx) or parts of your homepage.
Keep these files together and import each component where you use it. For a
custom logo, import `Logo` from `./components/logo` in `rdx.config.ts` and assign
it to `navbar.logo`.

For a custom homepage, create `components/home.tsx`. Import it from
`./components/home` in `rdx.config.ts` and assign it to `homepage.component`.
Keep the other React components used by your homepage in `components/` as well.

## The internal application

`.rdx/` is generated by `rdx prepare`, `rdx dev`, `rdx build`, and
`rdx start`. It contains the Next.js application and its build output.

Keep it out of version control. Do not treat it as a source directory:
preparation refreshes its runtime files. Your source of truth is the project
configuration, content, assets, and any components you own.

## Categories and URLs

Top-level folders become sidebar categories. An optional `_category.json`
sets a category's title and order. Page URLs follow their path inside `docs/`:
`docs/init/intro.mdx` becomes `/docs/init/intro`.

Use [relative MDX links](./document-links.mdx) to link one document to another.

## Versioned

With the optional versioning plugin, `versions.json` lists snapshots and
`versioned_docs/` stores them. Neither is needed to write your first page.
Learn more in [Versioning](../cat-04/versioning.mdx).
