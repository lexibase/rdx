## Your project

Organize your documentation, assets, and custom React components as follows:

```folder
my-docs/
  components/
    home.tsx
    logo.tsx
  docs/
    01-getting-started/
      01-intro.mdx
      02-installation.mdx
    02-examples/
      markdown.mdx
  public/
    images/
  package.json
  rdx.config.ts
  tsconfig.json
  .gitignore
  README.md
  .rdx/
```

Use `docs/` for content, `public/` for public files, and `rdx.config.ts` for
configuration. Write pages as `.md` or `.mdx`; both formats use the same
sidebar and page URLs. The creator includes example pages that you can replace.

For theme customization, create [rdx.css](../04-features/appearance.mdx) beside
`rdx.config.ts`.

## Custom components

Create a `components/` folder at the project root for your own React components,
such as a [custom logo](../04-features/custom-logo.mdx) or parts of your homepage.
Keep these files together and import each component where you use it. For a
custom logo, import `Logo` from `./components/logo` in `rdx.config.ts` and assign
it to `navbar.logo`.

For a custom homepage, create `components/home.tsx`. Import it from
`./components/home` in `rdx.config.ts` and assign it to `homepage.component`.
Keep the other React components used by your homepage in `components/` as well.

## The internal application

`.rdx/` is generated by `rdx prepare`, `rdx dev`, `rdx build`, and
`rdx start`. It contains the Next.js application and its build output.

Keep it out of version control. Do not treat it as a source directory:
preparation refreshes its runtime files. Your source of truth is the project
configuration, content, assets, and any components you own.

## Categories and URLs

Each top-level folder becomes a sidebar category. RDX derives the category
label from its name. For example, `01-getting-started` becomes **Getting Started**.

Start folder or file names with two digits and a dash (`00-` through `99-`)
to control sidebar order. Lower numbers come first and unnumbered entries
follow in alphabetical order. Set `order` in a page's frontmatter to override
its filename position. Add `navTitle` to shorten its sidebar label.

URLs keep the full folder path and omit ordering prefixes. For example,
`docs/01-getting-started/02-installation.mdx` becomes
`/docs/getting-started/installation`. Relative Markdown links use the actual
filenames, including their prefixes.

See [page frontmatter](./create-docs.mdx#page-frontmatter) or
[migrate an existing sidebar](../05-guides/migrating-sidebar.mdx).

## Versioned

With the optional versioning plugin, `versions.json` lists snapshots and
`versioned_docs/` stores them. Neither is needed to write your first page.
Learn more in [Versioning](../04-features/versioning.mdx).
